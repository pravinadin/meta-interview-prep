# Replan rules

Replan from evidence, not mood: each Saturday (and on Tue Nov 3, once recruiter answers arrive), check the signals below and change next week's issues. Mocks and sleep are never what gets cut.

## Saturday review (30 min)

1. Fill the Actual and Status columns in [scorecard.md](scorecard.md).
2. Group this week's [error-log](error-log.md) rows by pattern; the top 2 patterns get next week's redo slots.
3. Apply every rule below whose signal fired, and edit next week's issues to match.
4. Add one line to the replan log: what changed and why.

## Signals

| Signal | Change |
| --- | --- |
| Baseline: coding speed or C++ fluency "Weak" | Move 3 h from in-domain (weeks 1–2) to coding; add a 30-min STL drill every weekday in week 1 |
| Baseline: AI-enabled coding "Weak" | Add one extra AI drill per week; cut LeetCode volume by 4 problems to make room |
| Baseline: system design "Weak" | Add 2 timed designs in week 2; book a second design mock |
| Baseline: behavioral "Weak" | 15-min story rehearsal every weekday from Nov 2 |
| Recruiter: one coding round is classic (no AI) | Half of all problems with no AI; keep the AI drills as planned |
| Recruiter: both rounds AI-enabled | Swap 6 LeetCode problems for 2 extra AI drills |
| Recruiter: in-domain is not networking | Replace in-domain #2, #3 and #6 prompts with extra system designs |
| Problems below 80% of target | Drop designs #7 and #9 and the light-DP set; move those hours to coding |
| ≤ 25-min rate below target | Stop new problems; redo error-log problems by pattern until 2 clean solves in a row |
| Mock rated ≤ 2 | Debrief the cause, then 2 extra timed reps of that round type before the next mock |
| Missed 2+ weekdays | Run the 90-min minimum day; don't try to catch up everything |
| Loop date moves later | Repeat a week-2 style week with fresh problems and 2 more mocks |
| Loop date moves earlier | Jump to week 3's mock-and-polish schedule now |
